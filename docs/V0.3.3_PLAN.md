# VelaRi 0.3.3 Plan

**Status:** Next release

VelaRi 0.3.3 should be a polish release after the 0.3.2 project workflow improvements. It should improve developer experience and prepare the codebase for the typed compiler work planned for 0.4 without changing the language model substantially.

## Proposed scope

| Priority | Work item | Expected result |
| --- | --- | --- |
| P0 | Human-readable runtime values | Normal output is easier to read while a debug mode preserves structural values. |
| P0 | Better collection runtime diagnostics | Invalid indexes, missing keys, and invalid `length` calls include source context and actionable messages. |
| P0 | CLI command cleanup | Consistent help, version, exit status, and missing-file behavior across platforms. |
| P1 | Project test assertions | Add a small standard assertion function for `.vr` test programs. |
| P1 | Manifest validation | Report malformed or unsupported `vela.toml` fields instead of silently using defaults. |
| P1 | Example and documentation refresh | Add a collections and testing walkthrough using the cozy calm branding direction once assets are approved. |
| P2 | Formatting groundwork | Define stable formatting rules for source files before implementing `velari fmt`. |
| P2 | Release automation cleanup | Standardize source archives, checksums, and release notes. |

## Non-goals

VelaRi 0.3.3 should not introduce the full type-annotation system, generic types, native compilation, GUI APIs, or a new package registry. Those remain part of the VelaRi 0.4 design track.

## Release criteria

The release is complete when all existing examples and project tests pass, runtime errors identify their source operation, CLI behavior is covered by integration tests, malformed manifests fail clearly, and the release archive contains the documented source and checksum assets.

## Branding integration boundary

The compiler and test runner remain independent of visual assets. After the final logo, banner, and icon files are approved, the README and release templates can adopt the palette and asset names without changing compiler behavior.
