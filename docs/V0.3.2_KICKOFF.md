# VelaRi 0.3.2 Kickoff Plan

**Status:** Implemented in VelaRi 0.3.2.

## Purpose

VelaRi 0.3.2 should be a quality and tooling release following the 0.3.1 collection milestone. It should improve reliability without introducing a large language redesign. The milestone should make the current interpreter workflow easier to test, diagnose, and use from a clean checkout.

## Proposed scope

| Priority | Work item | Outcome |
| --- | --- | --- |
| P0 | Add CLI integration tests | `check`, `run`, `new`, version output, exit codes, and generated projects are covered automatically. |
| P0 | Add golden diagnostic tests | Error messages and source spans remain stable across releases. |
| P0 | Improve collection diagnostics | Invalid indexes, missing map keys, and invalid `length` calls report actionable errors. |
| P1 | Add collection mutation rules | Decide whether indexing assignment is supported and make unsupported forms fail clearly. |
| P1 | Add manifest discovery | `vela.toml` is located from the current directory and generated projects use normalized package names. |
| P1 | Add `velari test` | VelaRi projects can run source-level tests through the CLI. |
| P2 | Improve output formatting | Add a human-readable value display mode while preserving the debug output used by current examples. |
| P2 | Add Windows release guidance | Document local binary execution, Cargo installation, and PATH setup in the release notes. |

## Definition of done

VelaRi 0.3.2 is ready when a fresh clone can run the complete test suite without manual setup beyond Rust installation, all documented CLI commands have automated coverage, collection failures produce stable diagnostics, and a generated project can be checked and tested from its own directory.

## Branding dependency

The compiler implementation does not depend on visual assets. Branding assets can be integrated in a follow-up documentation and template pass after the final asset names and usage rules are confirmed.

## First implementation branch

After branding approval, create a focused branch or milestone issue with this order:

1. Add CLI test harness utilities.
2. Add diagnostic golden files.
3. Add collection error coverage.
4. Implement manifest discovery and normalization.
5. Add `velari test`.
6. Update the README and release notes.
7. Run Windows and Unix validation before publishing `v0.3.2`.
